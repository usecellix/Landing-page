01 — The Real Problem

Four Tools, Zero Connection

Every Indian CA uses the same four Microsoft tools every single day. The tragedy is that none of them know what the others are doing. A CA finishes a GST reconciliation in Excel, then manually types the summary into Word, then copies numbers into a Power BI dashboard, then writes an email in Outlook attaching the file. Each step is manual. Each handoff is fragile. Context is rebuilt from scratch every time.

📊

Microsoft Excel

Where all the raw numbers live — GST data, Tally exports, journal entries, reconciliations.

Doesn't know what report will be generated from its data
📈

Power BI

Where dashboards and visuals are created for client presentations and management reporting.

Doesn't know the logic behind Excel calculations
📝

Microsoft Word

Where audit reports, management letters, and working paper narratives are written.

Doesn't know which numbers came from which Excel formulas
📧

Microsoft Outlook

Where client communication happens — sending reports, sharing findings, requesting data.

Doesn't understand the attachments it sends or receives

The result is that a CA doing a single engagement — say, a GST audit for a client — touches all four tools in a single session, rebuilding context manually each time. The average Indian CA firm loses 8–12 hours per client per month to this invisible friction. Not to difficult intellectual work. To copying, pasting, and reformatting the same information across four disconnected tools.

The Core Insight

The problem isn't that any one of these tools is bad. Excel is powerful. Power BI is excellent for visualization. Word and Outlook work fine. The problem is that there is no shared memory, no shared context, and no intelligence that lives between them. CELLIX becomes that intelligence.

02 — The Product Vision

Not an Add-in. An Intelligence Layer.

"Prepare the GST reconciliation, create a summary dashboard, generate the audit report, and send the mismatch summary to the client."

One sentence. Four tools. Zero manual copying. This is where CELLIX goes.

The most important architectural insight in this entire document is this: CELLIX should not be thought of as four separate add-ins for four separate tools. That approach leads to four mediocre products that don't talk to each other. CELLIX must be built as a single intelligence core that happens to have four interfaces — one for each tool.

The Excel add-in is not the product. The AI core is the product. The Excel add-in is just the entry point — the place where CAs first encounter CELLIX because it's where they spend most of their time. But the intelligence that understands a client's financial data, the reconciliation that was just run, the mismatches that were found, and the approval that was given — that all lives in the CELLIX core, not inside Excel.

When the CA switches from Excel to Outlook, CELLIX doesn't forget what happened in Excel. When they open Word to write the audit report, CELLIX already knows which numbers to insert and where they came from. This is the vision: shared context across every tool in a CA's workflow.

04 — System Architecture

Three Layers, One Intelligence

The architectural principle is simple: there are three distinct layers, and the intelligence lives in only one of them. The interface layer is thin. The integration layer is plumbing. The context layer is the product.

Layer 1

Interface Layer

Where users interact — thin UI only

Excel Task Pane Add-in (Office.js + React)
Power BI Custom Visual / Add-in
Word Task Pane Add-in (Office.js)
Outlook Add-in (Office.js)
Google Sheets Sidebar (Apps Script) — Phase 2
Each interface sends user intent + local context to the CELLIX Core
Each interface receives structured patch plan and renders preview UI
Approval/rejection handled locally, result sent back to Core
Layer 2 — THE PRODUCT

Context Layer (CELLIX Core)

Intelligence, memory, domain logic — this is CELLIX

User Context: who the CA is, their client list, current engagement
Data Context: what's in the workbook, column meanings, relationships
Workflow Context: what was done, what was approved, what was sent
GST Rules Engine: encoded CBIC rules, ITC eligibility, rate tables
Tally Pattern Library: known export formats and cleaning rules
Audit Trail DB: every approved action across all tools, timestamped
LLM Router: sends each task to the right model at the right cost
Verifier Engine: tests AI outputs before they are ever shown to the user
Layer 3

Integration Layer

How tools connect — plumbing, not intelligence

Excel JavaScript API — read/write cells, ranges, formulas, sheets
Power BI REST API — push datasets, create visuals, refresh reports
Microsoft Graph API — access Word documents, Outlook emails, OneDrive files
Tally TCP/IP Connector — direct TDL integration for live ledger data
GSTN API — direct portal data fetch for GSTR-2A/2B reconciliation
Zoho Books / RazorpayX — SME accounting data import
PostgreSQL (audit trail) + Redis (session context cache)
Webhook system — event-driven triggers across all connected tools

06 — Implementation Roadmap

Phase-by-Phase Build Plan

This is not a "build everything at once" plan. Each phase adds a new platform only when the previous platform is genuinely excellent. The rule: if Excel experience is not 10x better than alternatives, there is no point adding Power BI. The foundation has to be unshakeable before expansion.

The Most Important Rule

Never move to the next phase until the current phase has at least 200 paying users who use it more than 3 times per week. Breadth without depth is how startups die. Excel has to be genuinely excellent before Power BI is touched.

07 — The Non-Negotiable Trust Layer

Approval Extends Across Every Tool

The single most important design principle of CELLIX — mandatory human approval before any action — must extend across every platform integration without exception. As CELLIX expands to Power BI, Word, and Outlook, the approval philosophy must be preserved. A CA who approves a reconciliation in Excel expects the same control over what goes into the client dashboard, the audit report, and the email.

📊

Excel — Cell-Level Approval

Every formula, every cleaned value, every reconciliation output is shown in a diff preview before writing to any cell. The CA sees exactly which cells will change, what they currently contain, and what they will contain after approval. Reject any individual patch without affecting others.

📈

Power BI — Dashboard Approval

Every dashboard generated by CELLIX is shown as a preview before being published to Power BI. The CA reviews each visual, verifies the data source, and approves the publish. No client dashboard is created without explicit CA sign-off. The approval is logged in the audit trail.

📝

Word — Document Approval

Every AI-drafted document is presented in Word's tracked-changes view, showing exactly what CELLIX wrote. The CA reviews the content, edits as needed, and approves the final version. The document is then locked with an approval timestamp and the CA's name as the approving professional.

📧

Outlook — Send Approval

Every AI-drafted email is shown in a preview panel with the recipient, subject, body, and attachments clearly displayed. The CA reads the full email, can edit any part of it, and then approves the send. CELLIX never sends any email autonomously. Every communication is approved before it leaves the firm.

🔗

Cross-Tool Audit Trail

The central audit trail records every approved action across every tool in a single chronological log for each engagement. A single engagement record shows: what was cleaned in Excel, which dashboard was published in Power BI, which report was drafted in Word, and which email was sent from Outlook — all linked to approvals and timestamps.

🔒

Data Never Leaves Without Consent

Client financial data shared with Outlook (in email attachments) or Power BI (in published dashboards) requires explicit approval at the point of sharing. CELLIX tracks what client data has been shared with whom and when — critical for professional liability and data privacy compliance under Indian data protection law.

Why This Is the Real Moat — Not the Features

Microsoft Copilot can generate an email. It can create a chart. It can summarize a document. What it cannot do — and structurally will not do — is enforce a mandatory approval workflow across all of these actions with a unified audit trail that an ICAI inspector can review. The approval architecture is not a feature. It is the product's professional identity. Every CA who uses CELLIX is implicitly saying: this tool is safe enough to touch my client files. That trust is built one approved action at a time, and it is the hardest thing for any competitor to replicate.

The End State: What CELLIX Becomes

Today, CELLIX is an Excel add-in with deep India CA workflows. In two years, with each phase executed well, CELLIX becomes the intelligence layer that connects every tool an Indian CA uses — not by replacing Microsoft's products, but by making them aware of each other for the first time. A CA who uses CELLIX doesn't work in Excel, then Power BI, then Word, then Outlook. They work in one connected financial workflow where context is never lost, nothing is ever applied without approval, and every action across every tool is documented in a single professional audit trail. That is not an add-in. That is a vertical AI operating system for Indian finance.
